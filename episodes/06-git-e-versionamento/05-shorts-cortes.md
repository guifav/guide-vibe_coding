# Shorts e cortes

Cada corte isola um conceito do versionamento, com gancho para o vídeo completo.

---

## Short 1 - Commit: a foto do código

**Gancho (0-3s):** "Você mudou 500 linhas e quebrou tudo. Como volta no tempo?"

**Corpo:** sem git, a resposta é pasta cheia de versao_final_v2.txt. Com git, a resposta é commit. Commit é a foto do código em um momento específico. Tem mensagem, autor, data. É imutável: depois de tirada, não muda.

**CTA:** "No vídeo completo eu conto a rede de segurança inteira. Link na descrição."

---

## Short 2 - Branch: mexer sem estragar o original

**Gancho:** "Você quer testar algo arriscado. Como faz sem quebrar o que tá no ar?"

**Corpo:** branch. Linha paralela na linha do tempo. Você cria uma branch a partir da main, mexe nela, e a main fica intocada. Main é a versão oficial, a que está em produção. Branch é o ramal onde você experimenta.

**CTA:** "O fluxo completo tá no vídeo principal do canal."

---

## Short 3 - Pull request: por que não joga direto na main?

**Gancho:** "Em time, em projeto sério, quase ninguém joga código direto na main. Por quê?"

**Corpo:** porque existe um portão. Pull request, ou PR, é o pedido formal de merge. Você diz: tenho uma branch pronta, olha o que mudei, posso juntar? Alguém revisa, comenta, aprova. Só depois o merge acontece. PR é o portão entre 'eu fiz' e 'isso está na main'.

**CTA:** "Quer entender o fluxo profissional inteiro? Vídeo completo no canal."

---

## Short 4 - Por que o deploy usa o repo, não seu computador?

**Gancho:** "O deploy não pega o código do seu computador. Sabe por quê?"

**Corpo:** seu computador é só de você. Se o deploy dependesse dele, o site cairia toda vez que você desligasse. O repo é a linha do tempo única do projeto. Quando o deploy roda, ele pega a main do repo. Por isso push é obrigatório: enquanto o código só está no seu computador, para o resto do mundo ele não existe.

**CTA:** "A rede de segurança inteira, até o merge, tá no vídeo principal."
